# Systems

## What is a system

A system is a function that reads and/or writes component data for a set
of entities during a simulation step. CueForge systems are pure with
respect to the `World` — given the same `World` and `dt`, a system
produces the same output, which is required for `DeterministicSimulation.md`
guarantees to hold.

## Step order (single simulation tick)

1. **Input application** — apply a pending `ShotInput` to the cue ball's
   `Velocity`/`AngularVelocity`, if a shot was just taken.
2. **Integration** — advance every ball's `Position` under its current
   `Velocity`, and `Velocity`/`AngularVelocity` under friction, per the
   ball's `BallState` (see `Rolling.md`, `Sliding.md` in `docs/physics/`).
3. **Broad-phase collision detection** — cheap bounding check to find
   candidate ball-ball and ball-rail pairs.
4. **Narrow-phase collision detection** — exact contact time/point for
   candidate pairs within this tick.
5. **Collision response** — resolve ball-ball (`docs/physics/Collision.md`)
   and ball-rail (`docs/physics/Rail.md`) impulses, including spin
   transfer (`docs/physics/Spin.md`, `docs/physics/English.md`).
6. **Pocket detection** — check ball position/velocity against pocket
   capture geometry (`docs/physics/Pocket.md`).
7. **Motion state transition** — update each ball's `BallState`
   (sliding → rolling → stationary, or → pocketed/airborne).
8. **Event emission** — emit all `Event`s generated by steps 3-7 in
   deterministic order (see `Events.md` for ordering rules).

## Fixed timestep

Systems run on a fixed timestep (not variable/frame-rate-dependent) to
preserve determinism; presentation-layer interpolation for smooth
rendering happens in `crates/renderer`, not in the core step.

## Ordering determinism

When multiple collisions are candidates within the same tick, they are
resolved in a canonical order (by entity ID, then by time-of-impact) so
that the same input always produces the same resolution order — see
`docs/physics/DeterministicSimulation.md` for the exact tie-breaking
rules.
